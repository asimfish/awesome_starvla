# F3 · 三头模型上的学习率控制：静态 LLRD 0.85 vs 漂移驱动 LLRD（1 卡，各 300 步）

**三句话结论。** (1) **漂移驱动的 LLRD（M1 机制）端到端工作**：第 35 层在第 100 次更新时越过阈值 1e-2，倍率按 0.5 → 0.25 → 0.125 → 0.062 → 0.05（下限）逐次减半；最终第 35 层漂移 0.039 vs 基线 0.052（−24%），可训练层均值 0.0023 vs 0.0029，OFT 头损失 0.253 vs 0.242、PI 0.328 vs 0.324、GR00T 0.427 vs 0.416，训练内 MSE 相同（0.0160 vs 0.0162）。(2) 但它**动手太晚**：顶层改写主要发生在第 50–100 次更新（warmup 结束、lr 最高的阶段），探针每 25 步一次、阈值 1e-2，等到第一次减半时已累积 0.023；要真正压住改写，阈值要到 1e-3 量级或探针更密。(3) **静态 LLRD 0.85、不硬冻结（R4 式）明显更差**：OFT 头 0.280、GR00T 0.477、MSE 0.0184，且低层出现锯齿状漂移——这暴露了单卡 bf16 训练路径的一个方法学问题（§3），它同样影响 F0 的漂移读数的解释。

## 1. 设置

与 F0 v3 三头运行完全相同的数据、步数、探针（[`../f0_libero_goal_smoke/README.md`](../f0_libero_goal_smoke/README.md) §3.5），只改学习率策略：

| 运行 | 冻结 | 学习率 | 控制 |
|---|---|---|---|
| 基线 `f0v3_multihead` | 视觉编码器 + LLM 0–17 层 | 18–35 层与嵌入 1e-5，头 1e-4 | 无 |
| a `f3_mh_llrd085` | 无 | 第 i 层 1e-5 × 0.85^(36−i)：第 35 层 8.5e-6、第 18 层 5.4e-7、第 0 层 2.9e-8；视觉编码器与嵌入 2.5e-8；头 1e-4 | 无（`calibrate_only`） |
| b `f3_mh_driftllrd` | 同基线 | 同基线（decay 1.0） | `DriftDrivenLLRD`：每次探针后，某层 token 级漂移 > 1e-2 → 该层 lr 倍率 ×0.5；< 1e-3 → ×1.1（上限 1）；下限 0.05 |

入口 `scripts/cluster/run_f3_llrd.sh`；LLRD 分组由 `starvla_lab.schedules.layerwise_lr_decay_groups` 生成（`heads.*` 与 `project_layers` 自动归入 head 组，不再需要 F0 的两个显式 lr 覆盖），倍率写进 `transformers` LambdaLR 的 `base_lrs`，探针 JSONL 每条记录带 `llrd_multipliers`。

## 2. 结果

| 运行 | 总损失末 50 步 | OFT 头 | PI 头 | GR00T 头 | 训练内 MSE（末） | 第 34 层漂移 @300 | 第 35 层漂移 @300 | 可训练层均值 @300 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 基线 | 0.981 | 0.242 | 0.324 | 0.416 | 0.0162 | 8.4e-4 | 0.052 | 2.9e-3 |
| a 静态 LLRD 0.85 | 1.104 | 0.280 | 0.347 | 0.477 | 0.0184 | — | 0.0045 | 1.1e-3（含 0–17 层 2e-4） |
| b 漂移驱动 | 1.008 | 0.253 | 0.328 | 0.427 | 0.0160 | 1.07e-3 | **0.039** | 2.3e-3 |

b 的控制轨迹（第 35 层 token 级漂移 → 倍率）：更新 75 次 0.0053 → 1.0；100 次 0.0233 → 0.5；125 次 0.0192 → 0.25；150 次 0.0278 → 0.125；175 次 0.0305 → 0.062；200 次 0.0348 → 0.05；之后 0.037–0.039，倍率停在下限。第 34 层始终在 1e-3 以下或附近（最高 1.07e-3），倍率保持 1。

a 的漂移随时间：0.0008（25）→ 0.0013（100）→ 0.0065（125）→ **0.0120（150）**→ 0.0016（175）→ 0.0049（200）→ 0.0050（225）→ 0.0010（250）→ 0.0003（275）→ 0.0006（300）；最大值多次落在第 17 / 21 层，mean-pool 视图 0.01–0.05——非单调、上下跳，与 v2 那种由嵌入驱动的锯齿形状类似，但这次嵌入已被换回、全部 36 层都在训练。

## 3. 读法与一个方法学发现

1. **控制器有效但迟滞**。它按设计降低了顶层的改写（−24%），头损失只付出 0.004–0.011 的代价。改进方向不在控制律，而在触发时机：F0 v3 显示第 35 层的漂移在第 50 次更新时已到 0.0038、75 次 0.0135，阈值应设在 1e-3 而不是 1e-2，或者用漂移的**增量**触发。R5 的起点因此改为 `drift_high 1e-3 / drift_low 1e-4`（写回 `matrix_R0_R9.yaml`）。
2. **静态 0.85 衰减在这个 regime 下不是替代硬冻结的好办法**：顶层 lr 只剩 8.5e-6、第 30 层 3.8e-6，头的损失全面变差；同时低层的"漂移"上下跳。这两点共同指向下面的问题。
3. **单卡无 DeepSpeed 路径的 bf16 更新量化。** StarVLA 以 `dtype=torch.bfloat16` 加载 VLM（`QWen3.py`），`STARVLA_DISABLE_DEEPSPEED=1` 时 AdamW 直接在 bf16 参数上更新，没有 fp32 主权重。bf16 相邻数值的相对间隔是 0.4%–0.8%；Adam 的单步更新量级 ≈ lr，对 lr 1e-5 与量级 0.02 的权重是 1e-5 / (0.02 × 0.006) ≈ 0.08 个 ulp——按最近舍入会被丢掉。于是：(i) 只有 |w| 小于约 2e-3 的权重（约 8%）在真正更新，且每步要么不动要么跳一个 ulp；(ii) 梯度方向越一致（三个头、flow-matching 的重复扩散步）越能越过舍入门槛，梯度噪声大的（单头 L1）更容易被整体吞掉——**F0 里"OFT 几乎不动骨干、三头动 240×"的对比，有一部分可能是 bf16 舍入门槛而不是任务需求造成的**；(iii) lr 低于 1e-6 的层（a 的第 30 层以下）只剩偶发的整 ulp 跳变，表现为非单调的漂移锯齿和更差的损失。多卡 DeepSpeed 路径（StarVLA 的正常用法）在优化器里保留 fp32 主权重，不受此影响。**F4 用 `trainer.lab.backbone_fp32: true`（骨干参数 fp32、计算仍走 bf16 autocast）重跑 F0 的两条主运行做校准**；在拿到 F4 之前，F0/F3 里所有关于漂移**绝对量级**与"OFT vs 三头"倍数的结论都应加上这条注。
