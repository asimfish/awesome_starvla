# F4 · fp32 主权重校准：单卡 bf16 路径一直在"吞"骨干更新（1 卡，2 条运行，各 300 步）

**三句话结论。** (1) **F3 §3 指出的问题是真的、而且大**：把可训练骨干参数升到 fp32（`trainer.lab.backbone_fp32: true`，计算仍走 bf16 autocast），其余与 F0 v3 完全相同，单头 OFT 的末 50 步 L1 从 0.247 降到 **0.183**（−26%），三头模型的 OFT / PI / GR00T 头从 0.242 / 0.324 / 0.416 降到 **0.178 / 0.293 / 0.353**，训练内 MSE 0.0167 / 0.0162 → 0.0135 / 0.0130。(2) **漂移的绝对量级大了一个数量级**：OFT 第 35 层 0.0003 → **0.026**，三头 0.052 → **0.484**；F0 里"OFT 几乎不动骨干、三头动 240×"的对比主要是 bf16 舍入门槛造成的，修正后三头仍是 OFT 的 19×，但 OFT 自己也在明显地改写顶层。(3) "三头不伤 OFT 头"仍成立（0.178 vs 0.183）；F0 / 跨头探针 / F2 / F3 中所有基于 bf16 checkpoint 的**绝对**读数都需要以此重新解释，下一步在 F4 的 checkpoint 上重跑跨头探针。

## 1. 设置

与 [F0 v3](../f0_libero_goal_smoke/README.md) §3.5 完全相同（LIBERO-goal，300 步，batch 8，骨干 lr 1e-5 / 头 1e-4，VLAct 式冻结视觉编码器 + LLM 0–17 层，探针每 25 次更新、跨场景 32 样本、token 级 CKA），只改两处：`embed_tokens` 加入冻结集合（F0 v3 消融已证明无代价，省 6 GB）；`trainer.lab.backbone_fp32: true`，即 `starvla_lab.train.integration.apply_backbone_fp32` 把 `qwen_vl_interface` 里**可训练**的 1,817M 参数（第 18–35 层 + 末层 norm + lm_head）就地升为 fp32，2,621M 冻结参数保持 bf16；StarVLA 的 `QWen3.forward` 与 `_train_step` 都包在 bf16 autocast 里，所以矩阵乘仍是 bf16，只是 AdamW 的更新落在 fp32 权重上——等价于 DeepSpeed 多卡路径里的 fp32 主权重。显存：OFT 44 GB（bf16 30 GB），三头 58 GB（47 GB）。节点 `tianyiyun-30109` GPU 5 独占；该节点 fork 出的 DataLoader 子进程分配不到内存（另一位用户占了 490 GB /dev/shm），因此 `num_workers 0`、主进程解码，s/step 不可与 F0 比较。入口 `scripts/cluster/run_f4_fp32.sh`。

对照组：bf16 的 `f0v3_oft_embedfrozen`（同样冻结嵌入）与 `f0v3_multihead`。

## 3. 读法

1. **bf16 路径的机制得到确认。** bf16 相邻值相对间隔 0.4%–0.8%，lr 1e-5 的 Adam 更新对量级 0.02 的权重只有约 0.08 个 ulp，按最近舍入被丢弃；只有小权重和梯度方向极一致的参数真正在学。fp32 主权重让同一 lr 下的更新全部生效，损失立刻好 26%——**F0/F2/F3 的所有 bf16 运行都是"骨干欠训练"的**。
2. **定性结论保留，定量结论改写。** 三头共监督仍让顶层被改写得远多于单头（19×），OFT 头在三头模型里仍不比单头差；但"OFT 微调几乎不碰骨干"不再成立——它把第 35 层改写到 0.026，与 bf16 下三头模型的水平相当。F0 §3.6 的跨头探针（bf16 checkpoint）测到的"OFT 保留度 99.5%"是欠训练骨干的读数；F2 里 `oft` 与 `pre` 骨干的差距（0.02–0.04）也来自一个几乎没动的骨干，fp32 骨干下差距应更大。这些都要在 F4 的 checkpoint 上重测。
3. **对方案的影响。** (a) 单卡冒烟一律开 `backbone_fp32`（`f0_libero_goal_smoke.yaml` 已改默认值），bf16 数字只作历史对照；(b) M1 的阈值量级再上调一个数量级：三头 fp32 在第 50 次更新时第 35 层已 0.05，OFT 0.003——R5 起点改为 `drift_high 1e-2 / drift_low 1e-3`，且控制器应在 warmup 内就开始工作（探针每 10 步）；(c) F3 的两条 LLRD 运行都在 bf16 下，其"静态 0.85 更差"部分是低 lr 层被舍入冻结所致，需在 fp32 下复跑才能评价 R4 式 LLRD。
4. **不变的部分**：探针口径（换回嵌入、token 级、跨场景批）在 fp32 下同样干净——冻结层精确为 0、第 0 步为 0、曲线单调饱和。

## 3. fp32 checkpoint 上的跨头探针：写入、迁移与代价（`cross_head_probe.json`）

同一批 2,048 个样本（goal 1,025 / spatial 1,023，20 条指令，每套 75/25 切分），六个骨干：预训练、F4 的两个 fp32 模型、F0 v3 的两个 bf16 对照。三种度量见 [F0 §3.6](../f0_libero_goal_smoke/README.md)；新增**H1 预注册指标**——QwenOFT 训练 prompt 里 8 个 🔍 查询 token 位置的隐状态，逐位置岭回归到对应的动作步（`--query_layers 33,34,35`）。

| 骨干 | H1 查询位可读性 L35：goal→goal / spatial→spatial / **goal→spatial** | pooled 可读性 L35：goal / spatial | 保留度 L35：微调→预训练 / 反向 |
|---|---|---|---|
| 预训练 VLM | 0.462 / 0.368 / −1.51 | 0.502 / 0.410 | 1.000 / 1.000 |
| OFT · bf16 | 0.509 / 0.389 / −2.51 | 0.501 / 0.410 | 0.998 / 0.998 |
| 三头 · bf16 | 0.503 / 0.392 / −1.26 | 0.493 / 0.402 | 0.976 / 0.967 |
| **OFT · fp32** | 0.562 / 0.430 / −0.08 | 0.537 / 0.426 | 0.870 / 0.803 |
| **三头 · fp32** | **0.581 / 0.420 / −0.03** | **0.566** / 0.413 | **0.794 / 0.651** |

（查询位可读性在 L33–L35 三层几乎相同；8 个查询位的 R² 彼此相差 < 0.02；pooled 可读性在 L30–L34 也呈同样次序：三头 0.556–0.569 > OFT 0.531–0.546 > 预训练 0.49–0.50。）

读法：

1. **微调确实把动作信息线性地写进了骨干——bf16 下看不到只是因为骨干没训练到。** 用 fp32 主权重训练 300 步后，OFT 查询位上的线性可读性从 0.462 涨到 0.562，pooled 特征从 0.502 到 0.537；三头模型更高（0.581 / 0.566）。F0 §3.6 的"五个微调骨干都没提高可读性、三头反而低 0.01"是 bf16 欠训练骨干的读数，**作废**。
2. **三头骨干的动作表征跨场景迁移得最好。** 在 goal 上拟合、在 spatial 上评测的线性解码器：预训练 −1.5（完全不迁移）、OFT −0.08、三头 **−0.03**（几乎不再为负）。这是 VLAct"多头共监督让骨干的动作表征更通用"在小规模上的第一条正面证据，而且是在预注册的度量上。同套内 spatial→spatial 两者相当（0.430 vs 0.420）。
3. **代价是对预训练表征的改写。** 第 35 层 token 级保留度 OFT 0.870、三头 0.794（反向 0.803 / 0.651）：三头模型把约五分之一的预训练顶层表征改成了线性不可恢复的形式，新表征里有三分之一是预训练解释不了的。它是"侵蚀"还是"写入"要看下游：F2 的 fp32 复测（冻结这两个骨干、接新头）正在跑。
4. **对 Q1/G2 的含义**：在同一批 checkpoint 上，查询位可读性（0.462 → 0.562 → 0.581）与 F0/F4 里各头的训练损失、F2 里新 OFT 头的收益方向一致，且比 pooled 可读性分辨力更强、跨套件数字可解释——它应当作为 G2 的主指标，pooled 与保留度作辅助。
